### Finding details

**SEC-001 (Medium): log forging and log flooding**
- **Evidence:**
  - uvicorn decodes the request target (`.venv/Lib/site-packages/uvicorn/protocols/http/h11_impl.py:205`, `unquote(raw_path.decode("ascii"))`), so `scope["path"]` can contain CR, LF and any Unicode character, including bidi controls.
  - security.py:92 (`logger.warning("Refused %s %s: %s", method, path, code)`) and :109 (`logger.exception(... %s %s", method, path)`) write the path unescaped and at full length. By contrast, the Host value at :80 is logged safely with `%r` and truncated to 100 characters.
  - **How a website triggers it:** a page open in the owner's browser sends `fetch("http://127.0.0.1:8765/x%0A<forged line>", {method: "POST", mode: "no-cors"})`. The browser sends Host `127.0.0.1:8765`, which is allowed, and a foreign Origin. The request is refused with 403, and the decoded path, newline included, lands in data\logs\agentdesk.log.
  - **Flooding:**
    - the request head may be up to 16 KB (h11 default, h11/_connection.py:69);
    - the log holds 1 MB × 6 files;
    - so about 375 such requests push every earlier line out of the log, startup and integrity errors included.
  - Each WebSocket attempt also logs two uvicorn warnings ("Unsupported upgrade request." and "No supported WebSocket library detected"), which is a second flooding path without injection.
  - No test sends `%0A`, `%0D` or very long paths (grep of tests/ found none).
- **Severity reasoning:**
  - CVSS 3.1 base is 5.4 (AV:N/AC:L/PR:N/UI:R/S:U/C:N/I:L/A:L). With the environmental adjustment for a non-authoritative troubleshooting log (IR:L, AR:L) it is about 4.2, at the low end of Medium.
  - It is the only issue any website can trigger. There is no data access and no code execution.
  - It does not block local Phase 1 use. It matters more once Phases 3 and 4 depend on the log to diagnose ingestion.
- **Remediation:**
  - in both log calls, log the path with `%r` (or escape control and format characters) and truncate it, for example `path[:200]`;
  - consider rate-limiting refusal log lines (for example the first N per minute, then one summary count);
  - add tests: POST `/%0d%0aFAKE` gives exactly one escaped log line; a 10 KB path gives a truncated line.

**SEC-002 (Low): restore during a running server**
- **Evidence:**
  - restore_db.py checks `is_port_free(settings.host, settings.port)` (lines 64-70) using the restore shell's own settings, then waits at `input(...)` (line 80) for as long as it takes, then calls `restore_backup` (line 88) without checking again.
  - `restore_backup` itself does no server check. No lock is shared with the server.
  - A server started during the prompt, or running with a different `AGENTDESK_PORT` or `AGENTDESK_HOST`, is not detected. The DEV report's limitation 5 notes the port part.
  - The server opens a connection only per request (connection.py:48-54), so on Windows the rename at backup.py:213 succeeds whenever the server is idle.
  - If a GET /api/v1/system arrives between `os.replace(db_path, kept_path)` and `os.replace(restoring_path, db_path)`:
    - `sqlite3.connect` (connection.py:18, default read-write-create mode) creates a new empty agentdesk.db;
    - the final replace then fails with "could not be replaced";
    - the server runs on an empty database, so later requests return JSON 500.
- **Impact:** a confusing owner-local integrity and availability problem. The original data stays in pre-restore-*.db. A cross-origin page can issue such GETs (no-cors) but cannot time them usefully.
- **Severity:** Low (about AV:L/AC:H/PR:L/UI:R/I:L/A:L). It needs concurrent owner actions.
- **Remediation:**
  - the server holds an exclusive lock file in the data folder for its lifetime; restore acquires it and keeps it through the swap;
  - check again immediately before replacing;
  - open request connections with a `file:...?mode=rw` URI, so a missing database gives a clear error instead of a new file;
  - tests: server on another port means restore is refused; a request on a missing DB creates no file.

**SEC-003 (Low): stale sidecars after restore when no database file exists**
- **Evidence:**
  - backup.py:210-217 moves `-wal`/`-shm` only when `db_path.exists()`. `-journal` is never considered.
  - If agentdesk.db was moved or deleted by hand while `agentdesk.db-wal`/`-shm` remained (they remain after a forced stop such as `taskkill /F`), line 218 places the restored copy next to the old WAL.
  - When SQLite opens a non-empty database and finds a `-wal` file, it opens WAL mode and replays the valid frames, even if the restored file's header records rollback-journal mode. This is SQLite pager behaviour; I did not execute it.
- **Test gap:**
  - test_tst_backups.py:284 and test_tst_config_cli.py:338 delete the sidecars before testing the no-database case;
  - the stale-sidecar tests (test_tst_backups.py:248, test_tst_config_cli.py:348) write garbage bytes, which SQLite discards as an invalid WAL header, so they cannot reveal a replay.
- **Impact:** the restored database may contain pages of the old one (corrupt or silently mixed data), which defeats the recovery control. Owner-local and uncommon.
- **Remediation:**
  - before the final replace, always move any `agentdesk.db-wal`, `-shm` and `-journal` into the pre-restore set, even when there is no main file;
  - after the swap, run `PRAGMA integrity_check` on the restored database;
  - test with a real, uncheckpointed WAL from another database.

**SEC-004 (Low): backup naming and retention (security view of D-1)**
- **Evidence:**
  - **D-1 as reported by TST:** the 12th same-second backup reuses the freed base name, sorts as the oldest (sort key at line 72), and is pruned at once. Then `parse_backup_name` (line 146) raises FileNotFoundError: a generic JSON 500 from the API, a traceback in the CLI.
  - **Same root cause, by code reading:**
    - if ≥10 backups carry future timestamps (the system clock was ahead, then corrected), every new backup sorts as the oldest, is deleted at once, and `create_backup` fails every time;
    - a single far-future name (for example agentdesk-20991231-...) makes `_startup_backup_due` (main.py:104-106) return False until that date, which stops automatic startup backups. The TST test covers only a 2-hour future offset;
    - a `PermissionError` from `unlink()` (line 153, for example a backup open in another program) propagates after a successful backup and reports failure;
    - `_unique_path` checks and then creates, and `sqlite3.connect(partial)` (line 102) is not exclusive, so two processes in the same second can write one file (DEV limitation 8).
- **Verified by reading:** pruning only touches names matching `BACKUP_PATTERN` inside the backups folder, and `unlink()` removes a link, not its target. So `pre-restore-*`, `failed-*` and foreign files are never deleted.
- **Severity reasoning:** not remotely triggerable, because POST /api/v1/system/backups needs the CSRF token and an allowed Host, and the CLI is local. The impact is on availability of the recovery backups, so Low.
- **Remediation:**
  - never prune the file just created;
  - number after the highest existing sequence for that second, or add milliseconds;
  - log and ignore future-dated names for the 24-hour rule;
  - catch and log `OSError` in pruning;
  - create the `.partial` file exclusively (`open(path, "xb")`) before connecting.

**SEC-005 (Low): inherited ACLs**
- **Evidence:** `icacls` shows `NT AUTHORITY\Authenticated Users:(I)(M)` and `BUILTIN\Users:(I)(RX)`, inherited from D:\, on D:\agentdesk and data\. Everything below inherits them: code, `.venv`, database, backups, logs.
- **Impact:** on a PC with more than one Windows account:
  - another account can read all AgentDesk data;
  - it can modify `app\*.py`, the scripts or `.venv`, which then run as the owner at the next start (cross-account code execution);
  - Phase 1 data is not sensitive, but Phase 4's planned `data\ingest_token` would be readable by every local user.
- **Severity:** Low on a single-account personal PC. It needs another local account, which is a different principal from "malware running as the owner".
- **Remediation:**
  - **Owner, after review**, restricts the folder, for example `icacls D:\agentdesk /inheritance:r /grant:r "%USERNAME%:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Administrators:(OI)(CI)F"`. Check the result before closing the window, because removing inheritance can lock out other tools.
  - **Planner:** before Phase 4, add a requirement that the data folder and the ingest token get an owner-only ACL. Respect DEC-009 (AgentDesk must not read the account name): a current-user SID from the process token, or a documented manual step, avoids that.

**SEC-006 to SEC-015 (Info)**
- **SEC-006:** uvicorn treats upgrade requests as plain HTTP while no `websockets`/`wsproto` package is installed (h11_impl.py:152-169), so today they still meet the Host check.
- **SEC-007:** CORP `same-origin` stops other sites loading any AgentDesk response, including /api/v1/session, as a no-cors subresource. COOP `same-origin` removes the opener's handle: a page that opened AgentDesk can currently change that tab's location or hash, which is harmless in Phase 1 because no route acts on load. Keep the rule "no state change on route load". Adding `require-trusted-types-for 'script'` changes the NFR-004 CSP string and needs planner and owner approval.

  - DEC-018 explicitly rejected hashes (option C) and records the dev sub-dependency limitation. Changing that is the owner's decision.

## Assessment of the testing defects D-1, D-2, D-3

  - The resulting 500 is generic JSON, and the stack trace goes only to the log, so nothing leaks.
- **D-2 (data folder is a file): no security impact.**
  - It happens in `create_app()` before the server binds.
  - The raw traceback, with local paths, appears only on the owner's own console.

## Controls verified by reading (positive observations; not proof of absence of defects)

- **Host allowlist (NFR-002):**
  - exact match after lowercasing against `127.0.0.1:<port>`, `localhost:<port>`, `[::1]:<port>`;
  - missing Host gives "" and a 400; no-port, wrong-port, trailing-dot, userinfo and long IPv6 spellings are refused;
  - latin-1 decoding cannot lowercase into an allowed value;
  - TST executed 20 variants × 4 paths and a real-server run.
- **CSRF (NFR-003):**
  - when an Origin is present it must equal `http://<Host>`, and `null` is refused;
  - the token is `secrets.token_urlsafe(32)`, new at each start, compared with `secrets.compare_digest` on bytes;
  - checks run before routing on every path;
  - the token is served only by a same-origin GET (no CORS headers, `no-store`, no cookies);
  - api.js retries once, and only after `csrf_token_invalid`, which is refused before routing, so a request never runs twice;
  - no state-changing GET, apart from the missing-file edge case in SEC-002.
- **Headers (NFR-004):**
  - the CSP has no `unsafe-inline`;
  - it is applied by a pure ASGI middleware to every response kind, including 400/403/415/404/405/500 and static files;
  - API responses get `no-store`; page and static responses get `no-cache`;
  - OpenAPI and docs are disabled; `server_header=False`, `proxy_headers=False`, access log off; debug off.
- **Static files:**
  - Starlette with `html=False` (no directory listing);
  - absolute paths refused; `realpath` + `commonpath` containment; symlinks not followed out of the folder; a different drive gives 404;
  - TST executed 22 + 14 traversal spellings.
- **Errors (NFR-006):** generic JSON 500 and 422 that never echo input; tracebacks go only to the log.
- **Logs (NFR-007):** no headers, bodies or token are logged (SEC-001 aside); 1 MB × 5 rotation; no token-like strings in the current log.
- **SQLite:**
  - every statement is constant or parameterized; no dynamic SQL;
  - WAL, `foreign_keys=ON`, `busy_timeout`, explicit `BEGIN IMMEDIATE` transactions;
  - each migration runs as `executescript` under `autocommit=True` (no implicit COMMIT) inside its own transaction;
  - SHA-256 checksum comparison; duplicate, 0000, non-UTF-8 and missing-file cases refused;
  - startup `quick_check` on a read-only connection.
- **Backups and restore:**
  - online backup API, then `.partial`, then `integrity_check`, then `os.replace`; failed copies are kept as `failed-*`;
  - pruning is pattern-only;
  - restore checks: name allow-list (`SAFE_NAME`), `..` refusal, `resolve(strict=True)`, exact parent match, `is_file`, integrity check, typed `RESTORE`, and the current database kept as `pre-restore-*` with its sidecars;
  - TST executed about 40 hostile names, including device names, ADS and UNC.
- **Startup (NFR-001):** host allow-list, port 1024-65535, port-in-use refusal before any startup work, and uvicorn binds only the validated host.
- **Scripts:** quoted paths; no execution of untrusted input; start.bat uses the explicit `.venv\Scripts\python.exe`; setup.bat keeps TEMP/TMP inside `.sandbox\tmp`, disables the pip cache and version check, and keeps the venv inside the repository.
- **Frontend (NFR-005):**
  - no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `eval`;
  - no inline scripts, styles or handlers, and no external URLs;
  - text inserted only as text nodes;
  - theme value checked against an allow-list; CSRF token kept in memory only.
- **Secrets and Git:** none found in code, tests, docs, scripts, the 2 commits or the log. `.gitignore` covers data/, .venv/, databases, WAL/SHM files, logs and caches.
- **CON-009:** by reading and TST-ISO, application code, scripts and tests write only inside the repository under the default configuration. Residual items are in SEC-013.
