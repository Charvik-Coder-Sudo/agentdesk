## Implementation summary

- **TASK-003:** the dependency files follow DEC-018. `requirements.lock.txt` came from `pip freeze` in a fresh `.venv`
  after `pip install -r requirements.txt`. It holds exactly the dependency closure of fastapi and uvicorn (checked:
  no extra or missing package). Note: fastapi 0.162.0 requires `opentelemetry-api`, so it is in the lock.
- **TASK-004:** an invalid host, port or log level raises `ConfigError`. `python -m app` prints the message and exits 1
  before creating any folder.
- **TASK-005:** a pure ASGI middleware, so it also covers error responses.
  - Order of checks for POST, PUT, PATCH and DELETE: Origin (403), then CSRF token (403), then JSON content type
    (415). A request without a valid token therefore always gets 403, whatever its content type (FR-009
    criterion 4); the 415 applies to requests that carry a valid token.
  - The state-changing checks apply to every path, not only `/api` (stricter; no non-API state-changing routes exist).
  - Static files and `/` carry `Cache-Control: no-cache` (always revalidate); `/api` carries `no-store`.
  - Unhandled exceptions return a generic JSON 500; the stack trace goes only to the log.
  - The token is compared with `secrets.compare_digest`.
- **TASK-006:** connections use `autocommit=True` (Python 3.12+), so `BEGIN IMMEDIATE` plus `executescript` stays one
  transaction. I verified that a failing script inside it rolls back completely. Checksums normalize CRLF to LF,
  so a Git checkout with `core.autocrlf=true` (set on this PC) does not count as an edit. Duplicate numbers, version
  0000, non-UTF-8 files and an applied migration whose file is missing all stop startup with a message.
- **TASK-007:**
  - Backup names use UTC time (sortable, not affected by daylight saving). Two backups in the same second get `-2`,
    `-3` suffixes.
  - Copies are written as `.partial`, integrity-checked, then renamed. A copy that fails the check is kept as
    `failed-<name>` and is not counted as a backup.
  - Retention manages only names matching `agentdesk-YYYYMMDD-HHMMSS-(manual|startup|pre-migration)[-N].db`.
  - Restore accepts any plain `*.db` name directly inside `data/backups` (so a `pre-restore-*` file can be restored
    to undo a restore). It copies through the SQLite backup API, which also reads a candidate's WAL, and moves the
    current database together with its `-wal`/`-shm` files to `pre-restore-<time>.db`.
- **TASK-008/009:**
  - The startup sequence runs inside `create_app()`, before uvicorn starts, so a refused start is a clean message
    and exit code 1.
  - The integrity check and the reading of applied migrations use a read-only connection, so a damaged file is
    never written.
  - Interactive API docs (`/docs`, `/redoc`, `/openapi.json`) are disabled: they load scripts from the internet,
    which the CSP forbids.
  - `python -m app` checks the port before starting and explains what to do if it is busy.
- **TASK-010 to TASK-012:** no inline scripts, styles or handlers. The skip link moves focus itself, because `#main`
  would collide with the hash routes. Focus moves to the page heading after navigation, but not on the first load,
  so Tab still reaches the skip link first (Appendix A step 19). "Create backup now" uses `aria-disabled` rather than
  `disabled` while working, so keyboard focus stays on it.
- **TASK-013/014:** `setup.bat` redirects TEMP/TMP to `.sandbox\tmp` and disables pip's cache and version check, so
  pip and ensurepip write nothing to the user profile.
- **TASK-015:** 122 tests (section "Validation").
- **TASK-016:** README and CHANGELOG.

### Defects found and fixed during this task

1. **Backslashes corrupted by shell heredocs.** Files I first wrote through bash heredocs had `\\` collapsed to `\`:
   - `app/static/js/router.js` line 19: a broken regular expression. Browsers would have failed to load the router
     and therefore the whole app.
   - `scripts/backup_db.py` and `scripts/restore_db.py`: invalid escapes, and a backspace character in two printed
     messages.

   Found with `node --input-type=module --check` and `python -W error`, fixed with exact edits, and confirmed that
   every other file has the intended backslashes. Unicode escapes such as `\u2713` in the JS files were turned into
   the literal UTF-8 characters, which works the same (files are served as UTF-8).
2. **`node --check` is not reliable for these files.** On Node 24.18.0, `node --check file.js` exits 0 for a `.js`
   file that uses `import`/`export` and contains a syntax error. A deliberately broken file and the broken
   `router.js` both "passed". The reliable form is `node --input-type=module --check < file.js`, which failed on the
   broken files and passes on all seven current files. TASK-024 (Phase 2, `tests/test_js_checks.py`) should use this
   form and keep a negative control.

### Test changes (CON-019: changed only with a recorded reason)

Both changes were made during my own first runs, before any report; both tests were wrong:

- `test_static.py::test_root_serves_index_html`: compared `response.text` with `read_text()`, which would break after
  an autocrlf checkout. It now compares bytes.
- `test_static.py::test_index_has_no_inline_scripts_styles_or_handlers`: the regex `<script\b[^>]*>\s*\S` matched the
  `<` of `</script>` (a false failure). It is now `<script\b[^>]*>(?!\s*</script>)`, and I confirmed it still detects
  `<script>alert(1)</script>`.

No test is skipped, removed or weakened.

## Known limitations

1. Browser behaviour (navigation, focus, theme persistence, health polling, the 400 px layout, the live region,
   and the absence of CSP violations in the console) is untested by me. It needs the owner's Appendix A checklist.
2. A short flash of the system theme may appear on load when the saved theme differs. Applying the saved theme before
   the first paint would need an extra blocking script; module scripts run after parsing.
3. `start.bat --open`, Ctrl+C shutdown, and the "server did not answer within 20 seconds" message were not exercised.
4. Backup file names use UTC times. The Settings page shows local time.
5. Restore is offline only. It relies on the port check: an AgentDesk started on a different port or data folder
   would not be detected. It also accepts any plain `*.db` name in `data/backups`, including `failed-*` copies,
   which are refused anyway by the integrity check if they are damaged.
6. Development sub-dependencies are not locked (DEC-018 limitation). Starlette's httpx deprecation warning is
   filtered in `pytest.ini`.
7. CON-009: setup and tests write only inside the repository. However, the agent harness itself stores
   background-command output under `C:\Users\Charvik\AppData\Local\Temp\claude\...`; that is the tool, not
   AgentDesk or its scripts. Creating a venv with the system Python could compile missing standard-library `.pyc`
   files under `C:\Python315`; I did not observe or rule this out.
8. Per-process lock only: a CLI backup and a GUI backup in the same second from two processes could pick the same
   name (very unlikely). The second would replace the first file, so one backup would be lost, but no data.
9. Headers in the log (Host values) are truncated to 100 characters and `repr`-quoted.

## Suggested edge cases for the testing-agent

- CSRF: token from an earlier run (included); `Origin: null` (included); `Origin` with a different port or
  `https`; a token with non-ASCII bytes; an empty `X-AgentDesk-CSRF`; a missing `Content-Type` together with a
  valid token (gives 415); `application/json; charset=utf-8` (should pass); `HEAD` and `OPTIONS` requests.
- Host: `[::1]:8765` (included), `localhost.:8765`, uppercase, a missing Host header, a Host with userinfo, very long
  Host values, and the log line content.
- Config: ports 1023, 1024, 65535, 65536 (included); whitespace around values; a relative `AGENTDESK_DATA_DIR`.
- Migrations: an empty migrations folder; `0000_x.sql`; a non-UTF-8 file; a file with `COMMIT;` inside (known
  unsupported); a BOM at the start of a file; an empty (0-byte) existing database file.
- Backups: more than 10 backups plus foreign files (included); names like `agentdesk-20261031-071036-manual-2.db`;
  a read-only backups folder; simultaneous POSTs; a backup while another connection holds a write transaction.
- Restore: names with `..`, `:`, absolute and UNC paths, `CON.db`, trailing spaces or dots, a symlink or junction
  in `data/backups` pointing outside; restoring a `pre-restore-*` file that has a `-wal` file next to it.
- Integrity: a truncated database file; a database whose `-wal` is damaged; confirm that no `-wal`/`-shm` writes
  change the main file's hash.
- Static: `/static/` (directory), encoded traversal (`%2e%2e`), `/static/index.html`, MIME types of all files.
- JavaScript: add `node --input-type=module --check` with a negative control (TASK-024); confirm plain `node --check`
  misses ESM syntax errors on Node 24.18.0.
- Scripts: `restore_db.py restore` with stdin closed (EOF means cancel); `backup_db.py create` with no database.

## How it works (for the owner)

### The important files

| File | What it does, in plain words |
|---|---|
| `scripts\setup.bat` | Run once. Makes a private Python folder `.venv` inside the project and installs the exact package versions from `requirements.lock.txt`. |
| `scripts\start.bat` | Starts AgentDesk and opens your browser at http://127.0.0.1:8765. |
| `app\__main__.py` | What `python -m app` runs: checks the settings, makes sure the port is free, then starts the web server. |
| `app\main.py` | Builds the application. Before accepting any request it checks the database, makes a backup if needed, and applies database updates. |
| `app\core\security.py` | The "doorman": rejects requests addressed to a foreign host name, rejects changes without the secret page token, and adds browser security headers to every answer. |
| `app\api\system.py` | The web API: health, system information, the page token, the backup list, and "create a backup". |
| `app\database\backup.py` | Makes and checks backups, keeps the newest 10, and does restores. |
| `app\database\migrations.py` | Applies the numbered SQL files in `migrations\` once each, and notices if one was edited later. |
| `app\static\index.html`, `css\app.css`, `js\*.js` | The page you see: header, menu, theme choice and pages. Plain HTML, CSS and JavaScript, with no build step. |
| `scripts\backup_db.py`, `scripts\restore_db.py` | Backup and restore from the Command Prompt. |

### How "Create backup now" flows from the page to the database

1. You click **Create backup now** on the Settings page (`js\pages\settings.js`).
2. `js\api.js` first asks the server for this run's secret token (`GET /api/v1/session`). Then it sends
   `POST /api/v1/system/backups` with the token in the `X-AgentDesk-CSRF` header and `{}` as JSON.
3. The doorman (`security.py`) checks four things: the address is 127.0.0.1:8765; the request came from the
   AgentDesk page (Origin); the token matches; the body is JSON. If any check fails, the answer is a 400, 403 or 415
   error and nothing is created.
4. `api\system.py` calls `create_backup()` in `database\backup.py`. That function:
   - copies the live database with SQLite's safe "online backup" into `data\backups\...partial`;
   - runs `PRAGMA integrity_check` on the copy;
   - renames it to `agentdesk-YYYYMMDD-HHMMSS-manual.db`;
   - deletes backups beyond the newest 10.
5. The server answers `201` with the backup's name. The page shows "Backup created: ...", announces it for screen
   readers, and reloads the backup list without reloading the page.

### Why this approach

- **One small, standard stack:** FastAPI plus SQLite plus plain JavaScript. Nothing to build and few packages to
  keep updated.
- **The security checks are in one place (the doorman),** so every current and future endpoint gets them
  automatically.
- **The database is checked read-only before anything else,** so a damaged file is never made worse. Backups
  happen automatically before any database update.
- **Exact package versions are locked,** so a fresh setup installs exactly what was tested.
